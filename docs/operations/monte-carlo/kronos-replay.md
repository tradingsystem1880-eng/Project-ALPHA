# Kronos synthetic OHLCV with fresh engine replay

[Four-family overview](README.md) · [outputs and units](README.md#read-the-outputs)

## Purpose and question

Ask: **how does the unchanged strategy execute on market paths generated by this model?**
Kronos generates OHLCV rather than account returns. ALPHA rebuilds strategy inputs and runs fresh
canonical execution for each path; it does not replay the observed signal or resample its profits.

## Inputs, conditioning period and execution

This command does not locally fit Kronos weights. It conditions the selected pretrained model on
the last configured context bars of the source validation's real first training prefix. It
generates the remaining tail on the snapshot's exact frozen future timestamps, without consuming
observed future OHLCV. Default output is 128 separately seeded tails.

ALPHA rejects malformed lengths, nonfinite/nonpositive OHLC, or negative/nonfinite volume. It
preserves raw output and projects only high/low enough to enclose open/close, recording adjustments.
Open, close and volume stay unchanged. Physical enclosure does not establish economic realism.

For each tail, ALPHA joins the real prefix to generated bars, prepares strategy-dependent inputs
and runs a fresh canonical OOS portfolio. Source strategy parameters, sizing, costs,
train/test/embargo geometry and dividend inputs are retained. This is fresh execution per path,
not a portfolio reset for every fold. Synthetic corporate actions are not generated. Generated
tail length and scored OOS return horizon differ; engine output must match source OOS geometry.

## Outputs, units and interpretation

Artifacts contain observed OOS equity, raw/projected OHLCV, engine account-return paths,
per-path metrics, model diagnostics and calibration origins. Prices/volume retain source
instrument conventions; the common terminal returns and drawdown depths are decimal fractions,
and loss streaks count account-return periods. Compare generated-path outcomes and projection
counts with the observed path; do not interpret the observed path's rank as a no-edge test.

## Calibration and limits

A matching rolling-origin evaluation binds symbol, snapshot, research cutoff, exact bar history,
model/tokenizer identities/revisions and device. Post-pretraining-cutoff CRPS must beat both
random-walk and stationary-bootstrap baselines, with sufficient origins and empirical interval
coverage, to avoid the weak/insufficient-calibration warning. See the
[implemented adequacy checks](../../../apps/alpha-cli/src/alpha_cli/monte_carlo_cmds.py#L116).

Evaluation context, horizon and sampling controls need not match the Monte Carlo tail's settings.
Those diagnostics therefore do **not** directly calibrate the full generated joint path
distribution or strategy-loss/ruin probabilities. Pretraining overlap remains disclosed; sparse
skill, mutable revisions and non-exact device determinism warn. A model's synthetic paths can
miss structural breaks, rare events, execution effects or market constraints. Independently
generated assets are not a coherent portfolio scenario. Model-generated evidence is not edge.

## Reproducibility and evidence

Use the Kronos command in the [overview](README.md#run-and-reproduce). Preserve source validation,
snapshot and cutoff hashes, forecast-evaluation manifest/origin hashes, model/tokenizer revisions,
device, context, temperature/top-p/top-k, versions and all raw output. Each tail uses the namespace
`monte_carlo.kronos.path.{index}`. A seed alone does not promise cross-device bitwise reproducibility.
