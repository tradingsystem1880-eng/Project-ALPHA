# Documentation index

Where each kind of document lives, and how long it stays current. Tasks are routed by the root
[`CONTEXT.md`](../CONTEXT.md); documentation work starts at [`docs/CONTEXT.md`](CONTEXT.md). Rules live in
[`reference/invariants/`](reference/invariants/documentation.md) and the command list in [`reference/`](reference/commands.md).

**What works today:** [`STATUS.md`](../STATUS.md) (generated). **What the codes mean:** [glossary](reference/glossary.md).

## Lifecycle

| State | Meaning | Edited how | Where |
|---|---|---|---|
| Living | Describes the system or a procedure as it is now | Updated in place when behaviour changes | `ARCHITECTURE.md`, `reference/`, `governance/` (hand-written files), `operations/` |
| Decision | Records a choice and its reasons | Decision text is not rewritten; dated status notes and forward links are added when a newer record supersedes it | `adr/` |
| Intent | Dated design or plan for a piece of work | Status lines updated; every plan carries one `**Delivery state:**` line; finished task folders move to `work/archive/YYYY-MM/` | `work/`, `roadmap/` |
| Record | True as of its date; kept for provenance | Appended to or left as-is; path-only link fix-ups allowed (`BUILD-STATUS.md` and `build-status/` are frozen) | `BUILD-STATUS.md`, `build-status/`, `records/` (including the old design specs in `records/specs/`), `operations/retrospectives/` |
| Archive | No longer current; kept for history | Not edited | `archive/` |
| Generated | Produced by a tool; never hand-edited | Regenerated by its command (below) | `roadmap/README.md`, parts of `governance/` |

## Folders

| Path | What belongs there |
|---|---|
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | Current package boundaries, layered DAG and runtime components. |
| [`BUILD-STATUS.md`](BUILD-STATUS.md) | Frozen delivery history from 2026-10-01 to 2026-11; history since is git log and pull requests. |
| [`build-status/`](build-status/) | Quarterly archives of older `BUILD-STATUS.md` entries, moved verbatim: [2026 Q2](build-status/2026-Q2.md), [2026 Q3](build-status/2026-Q3.md). |
| [`reference/`](reference/commands.md) | The file system's reference layer: `invariants/` (rules), `project/` (what each part is for, the owner's decisions), generated `commands.md`, `glossary.md`; at most 200 lines each. |
| [`adr/`](adr/README.md) | Architecture decision records `NNNN-*.md`; the README is the index and supersession map. |
| [`context/`](context/README.md) | The canonical [feature readiness checklist](context/feature-readiness-checklist-2026-10-27.md) (the full-scope owner). The retired navigation maps are in `archive/2026-11-context-maps/`. |
| [`governance/`](governance/README.md) | Capability/authority matrix, OpenAPI operation classification, dependency licences, risk register and provenance records. |
| [`operations/`](operations/README.md) | Living runbooks and operating guides (development loop, harness, research workflows, Monte Carlo guides). |
| [`operations/retrospectives/`](operations/retrospectives/) | Dated retrospectives `YYYY-MM-DD-<slug>.md` with a `## Watch-outs` section. |
| [`records/`](records/README.md) | Dated one-off records: owner decisions and exceptions, delivery notes, handovers, [audits](records/audits/) and [investigations](records/investigations/). |
| [`work/`](work/archive/README.md) | One folder per task, `YYYY-MM-DD-<slug>/`, holding the stage outputs `01-brief.md`, `02-plan.md`, `04-verify.md`, `05-handoff.md` ([delivery pipeline](../workflow/CONTEXT.md)). |
| [`work/archive/`](work/archive/README.md) | Finished tasks by month (`YYYY-MM/`); plans archived before 2026-11-14 are single files there. |
| [`records/specs/`](records/specs/) | Dated design specs from 2026-06 to 2026-09 (historical). |
| [`roadmap/`](roadmap/README.md) | Generated index of live plans, [backlog](roadmap/backlog/) items (wanted features with no plan yet) and staged [refactors](roadmap/refactors/). |
| [`assets/`](assets/) | Images referenced by documentation. |
| [`archive/`](archive/README.md) | Historical prompts, one-off research and old run output, with a table of where each file came from. |

## Generated files

Do not edit these by hand; rerun the command and commit the result.

| Files | Command |
|---|---|
| `docs/governance/capability-authority-matrix.md`, `docs/governance/openapi-operation-classification.json` | `uv run python scripts/check_openapi_operations.py --write` (without `--write` it checks) |
| `docs/roadmap/README.md` | `uv run python scripts/roadmap_index.py` (`--check` verifies freshness) |
| `docs/reference/commands.md` | `uv run python scripts/commands_reference.py` (`--check` verifies freshness) |
| `STATUS.md` (from `docs/roadmap/capabilities.toml`) | `uv run python scripts/status.py` (`--check` verifies freshness) |

To find a document, see [Finding anything else](../CONTEXT.md#finding-anything-else) in the root `CONTEXT.md`;
search ranks living documents ahead of records and archives.

## Plan lifecycle

A wanted feature with no plan is one short file in [`roadmap/backlog/`](roadmap/backlog/); staged
structural refactors use [`roadmap/refactors/`](roadmap/refactors/). Turning either into delivered
work follows the [delivery pipeline](../workflow/CONTEXT.md), which owns the task-folder
convention, the plan's `**Delivery state:**` line and archiving. After any change to a plan or
backlog item run `uv run python scripts/roadmap_index.py`.
