# Documentation index

Where each kind of document lives, and how long it stays current. Start with
[`AGENTS.md`](../AGENTS.md) and [`CLAUDE.md`](../CLAUDE.md); the [context index](context/README.md)
maps capabilities to their owning documents.
The file system starts at the root [`CONTEXT.md`](../CONTEXT.md); rules and the command list live in [`reference/`](reference/commands.md).

**What works today:** [`STATUS.md`](../STATUS.md) (generated). **What the codes mean:** [glossary](reference/glossary.md).

## Lifecycle

| State | Meaning | Edited how | Where |
|---|---|---|---|
| Living | Describes the system or a procedure as it is now | Updated in place when behaviour changes | `ARCHITECTURE.md`, `context/`, `governance/` (hand-written files), `operations/` |
| Decision | Records a choice and its reasons | Decision text is not rewritten; dated status notes and forward links are added when a newer record supersedes it | `adr/` |
| Intent | Dated design or plan for a piece of work | Status lines updated; every plan carries one `**Delivery state:**` line; Completed or Superseded plans move to `superpowers/plans/archive/YYYY-MM/` | `superpowers/specs/`, `superpowers/plans/`, `roadmap/` |
| Record | True as of its date; kept for provenance | Appended to or left as-is; path-only link fix-ups allowed | `BUILD-STATUS.md`, `build-status/`, `records/`, `operations/retrospectives/` |
| Archive | No longer current; kept for history | Not edited | `archive/` |
| Generated | Produced by a tool; never hand-edited | Regenerated by its command (below) | `roadmap/README.md`, parts of `governance/` |

## Generated files

Do not edit these by hand; rerun the command and commit the result.

| Files | Command |
|---|---|
| `docs/governance/capability-authority-matrix.md`, `docs/governance/openapi-operation-classification.json` | `uv run python scripts/check_openapi_operations.py --write` (without `--write` it checks) |
| `docs/roadmap/README.md` | `uv run python scripts/roadmap_index.py` (`--check` verifies freshness) |
| `STATUS.md` (from `docs/roadmap/capabilities.toml`) | `uv run python scripts/status.py` (`--check` verifies freshness) |

To find a document, run `uv run python scripts/fs.py search "QUERY"` (`--kind`, `--limit`,
`--format json`): it searches the tracked documentation folders above and ranks living
documents ahead of records and archives (`BUILD-STATUS.md`, `build-status/`, `records/`,
`archive/`, `superpowers/plans/archive/`), labelling each result `live` or `archived`.

## Plan lifecycle

1. **Backlog.** A wanted feature with no plan is one short file in
   [`roadmap/backlog/`](roadmap/backlog/) (status `Idea` or `Scoped`, rough size, dependencies,
   sources). Staged structural refactors use [`roadmap/refactors/`](roadmap/refactors/). W01–W19
   scope stays owned by the [feature readiness checklist](context/feature-readiness-checklist-2026-10-27.md).
2. **Plan.** `/plan-feature` writes `superpowers/plans/YYYY-MM-DD-<slug>.md` with a `FeaturePlan`
   block and a `**Delivery state:**` line: `Implemented – qualification pending`, `In progress`,
   `Blocked` or `Planned`. Remove the backlog file it replaces.
3. **Archive.** When the work is merged (`Completed — <evidence>`) or replaced
   (`Superseded by <relative path>`), `git mv` the plan to `superpowers/plans/archive/YYYY-MM/`
   and fix links to it. After any of these steps run `uv run python scripts/roadmap_index.py`.
